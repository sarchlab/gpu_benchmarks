# Parametric Trace (`.ptrace`) — Method (as implemented)

This document describes the method **as it actually works in `tracer/`** today,
function by function. It is the method-of-record; the aspirational rationale is in
[`ptrace_design.md`](ptrace_design.md), the on-disk byte layout in
[`../tracer/FORMAT.md`](../tracer/FORMAT.md), and phase status in
[`../PTRACE_PLAN.md`](../PTRACE_PLAN.md).

The implementation is a **converter**: it ingests the Accel-Sim traces gpubench
already collects and re-encodes them. It does not yet instrument the GPU directly
(the live NVBit driver is deferred). Everything below therefore operates on an
already-collected trace, but the synthesis/verification machinery is exactly what
a sampled live tracer would use.

## Mechanisms at a glance

The method is a stack of independent mechanisms, each exploiting a different kind
of redundancy and each gated so it can only ever shrink the trace, never corrupt
it. The unifying principle: **classify, model what's provably regular, capture the
rest, and verify against an equivalence check** — byte-equivalence for the
lossless tiers, cache-behavior equivalence for the lossy one.

| # | Mechanism | Exploits | Lossless? | Gate / safety |
|---|-----------|----------|-----------|---------------|
| §1–2 | Static/dynamic split + ISA dedup + columnar zstd | per-PC invariance; relaunch reuse | yes | exact re-emit |
| §4 | Affine address recipes (tiers 0–3) | addresses affine in `(block,warp,iter)` | yes | self-verify each class; else record |
| §5 | Tier-5 residual column | bounded indices in recorded gathers | yes | exact token regen |
| §6 | Sampled synthesis (Mode 2) | SPMD block similarity | yes | byte-compare each synth block; else record |
| §6 | Grid extrapolation (`--grid`) | affine recipes evaluate at any coord | yes\* | **unverified** (no ground truth at new size) |
| §9 | Offline SASS analysis | the binary already encodes structure | n/a (a prior) | conservative; verify gate backstops |
| §10 | Tier-7 statistical (lossy) | gather *pattern* ≪ gather *information* | **no** | cache-behavior equivalence; else record |

Tiers 0–6 are lossless and reconstruct the trace byte-for-byte. Tier-7 is opt-in,
lossy, and for cache/perf simulation only. The sections below detail each.

## 0. Inputs and the lossless contract

The input is an Accel-Sim `traces/` directory: one or more `kernelslist*` files,
optional `stats*` files, and a `*.trace.zst` container per kernel launch. The
container (`container.go`) is the bb_triosim format — a JSON header, the `.traceg`
text header, a raw-content dictionary (thread block 0), and one zstd frame per
thread block.

The whole method preserves a **lossless contract**: `ptrace expand` reproduces the
original `.traceg` byte-for-byte (and `kernelslist`/`stats` verbatim), so BBSim
consumes expanded output unchanged. Every lossy-looking step (address modeling,
synthesis) is gated by an exact equality check and falls back to verbatim storage
on any mismatch. Nothing is ever stored that cannot be regenerated byte-identically.

## 1. Static / dynamic decomposition (`accelsim.go`)

Each `.traceg` instruction line is

```
PC  mask  dst_num [Rdst]  opcode  src_num [Rsrc...]  W [mode payload...]  imm
```

`parseLine` splits it into:

- **`StaticInst`** — the part that is invariant for a given PC: `dst_num [Rdst]`,
  `opcode`, `src_num [Rsrc...]` (joined as `Middle`), the memory width `W` (or the
  `0` non-memory marker), `IsMem`, and the trailing `Imm`.
- **`DynInst`** — the part that varies per dynamic instruction: `Mask`, and for
  memory ops the address compression `Mode` (0 `list_all`, 1 `base_stride`,
  2 `base_delta`) and its `Payload` tokens.

`ParseTraceg` accumulates the static content into an ISA map keyed by PC and
**hard-errors** if any PC's static content is ever inconsistent across its dynamic
occurrences — that would mean the decomposition is unsafe for that kernel.
`EmitTraceg` is the exact inverse and is what guarantees byte-identical expansion.

A `Block` is one thread block: its `(X,Y,Z)` coordinates and a slice of warps,
each a slice of `DynInst`.

## 2. Static table, deduped (`ptrace.go`)

`buildISA` sorts the PCs, builds an `ISATable` (parallel `Pcs`/`Insts` arrays), and
assigns each PC a dense id. The table is content-hashed (`hash()`); identical
tables across relaunches/sweep points are written **once** under `isa/<hash>.json`
and referenced by every invocation that shares them. This captures the
relaunch-redundancy axis.

## 3. Columnar dynamic payload (`ptrace.go`)

The per-launch dynamic stream is stored column-major, then zstd'd as one window.
Full mode (`encodeDyn`, dyn version 3) emits six length-prefixed sections:

```
[A struct][B pc][C mask][R recipes][S selector][D residual]
```

- **A** — block/warp structure: block coords, warp count, per-warp instruction
  count. (Only executed blocks are stored; within a block all warp slots are
  present, empty warps have `insts = 0`.)
- **B** — the dense PC id of every instruction (uvarint).
- **C** — the 32-bit active/predicate mask of every instruction.
- **R** — the recipe table (§4).
- **S** — a per-instance class selector, only for multiclass modeled PCs.
- **D** — the residual address column for memory instructions **not** modeled (§5).

A memory instruction whose PC is modeled writes **nothing** to D (and only a small
class id to S when multiclass); its addresses are regenerated from the recipe.

## 4. Address recipes (`recipe.go`) — the modeling step

The goal is to replace a memory instruction's per-instance base addresses with a
formula. For each static memory PC, `fitRecipes`:

1. **Groups instances by encoding class** = `(mode, constant tail)`. For modes 1/2
   the payload is `[base, tail...]`; the `tail` (e.g. the stride token) is the part
   that is constant within a class. Modes other than 1/2 (and any base that fails
   to parse as hex) are left unmodeled.

2. **Gates on regularity.** A PC is modeled only if its class assignment is
   **index-determined** — every instance at a given `(bx,by,bz,warp)` uses the same
   class, so the class is a function of indices, not data — and there is real tail
   reuse (`nClasses == 1`, or `nClasses·2 ≤ nInstances`). A PC whose class changes
   within one `(block,warp)`, or that has a near-distinct class per instance
   (gather / PRNG), fails the gate and stays recorded.

3. **Fits an exact integer-affine base.** For each class, the base address must be
   an exact function

   ```
   base = c0·bx + c1·by + c2·bz + c3·warp + c4·occ + c5
   ```

   where `occ` is the occurrence index of the PC within its warp (a loop-iteration
   proxy, recomputed identically on encode and decode). `fitAffine` solves this
   over the rationals (`math/big.Rat`, Gaussian elimination to RREF) and **requires
   an integer solution** that reproduces every sampled point exactly. Only columns
   that actually vary are solved; constants fold into the intercept.

4. **Self-verifies.** Each fitted class regenerates its recorded base **token** and
   must match byte-for-byte (this also guards the hex formatting). Any failure
   drops the whole PC back to recorded.

The recipe stores, per class, the `mode`, the constant `tail`, and the six affine
coefficients. `Coverage` records how many memory PCs / instructions were modeled.
This covers taxonomy tiers 0–3 (constant, affine, piecewise via multiclass, tiled).
Tiers 4 (PRNG-from-seed) and 5 (recorded index column) are **not yet** emitted;
those accesses currently land in the residual column, losslessly.

## 5. Residual column for unmodeled accesses (`tier5.go`)

Unmodeled memory instructions are still stored compactly. `encodeResidual`
reconstructs the per-active-lane address list (the active-lane count comes from the
mask, so it is not stored), then writes `[mode byte][uvarint base][zig-zag varint
deltas…]`. `decodeResidual` regenerates the **exact** original payload tokens for
the mode, so it remains lossless. This is far smaller than the text payload for the
bounded indices real gathers touch, but unlike a recipe it does not extrapolate.

## 6. Sampled collection + synthesis (`sample.go`, `synth.go`) — P3

This is the part that makes storage (and, with a live driver, collection time)
decouple from problem size. `ConvertSampled` produces a **sampled** payload
(dyn version 4):

1. **Corner sample** (`cornerSample`). Select the blocks whose every coordinate is
   one of the two smallest distinct values on its axis — at most `2×2×2 = 8` blocks
   regardless of launch size. Two values per varying axis is the minimum the affine
   solver needs to fix a slope, which is why the recipes extrapolate to the whole
   grid.

2. **Fit recipes on the sample only** (`fitRecipes` over the sample blocks).

3. **Synthesize + verify-or-fallback** (`buildSamplePlan`). For every non-sample
   block, `SynthBlock` replays the template block's per-warp shape (`pc`, `mask`)
   and recomputes each modeled memory instruction's base at the new coordinates;
   the result is compared to the real block with `blockEqual` (coordinates, warp
   shape, and every instruction's pc/mask/mode/payload). Any block that does not
   reproduce **exactly** is demoted to *recorded*. A sampled `.ptrace` is therefore
   still losslessly equal to the original — synthesis can only shrink it.

The sampled payload stores only recorded blocks (verbatim, every memory access as a
residual — a block is recorded precisely because a recipe did **not** reproduce it),
plus the recipes and a compact plan:

```
[A struct][B pc][C mask][R recipes][D residual][F flags][G coords]
```

- **A** carries the recorded blocks' structure but **no coordinates**.
- **F** — total block count, the template's slot in the recorded list, and a bitset
  (1 = synth, 0 = recorded).
- **G** — a zig-zag `(dx,dy,dz)` coordinate delta from the previous block, for
  *every* block in order.

A synthesized block thus costs only **one flag bit plus its coordinate delta** —
both near-constant streams for a dense grid that zstd reduces to almost nothing.
The payload is dominated by the (problem-size-independent) sample, so a
fully-synthesizable kernel's sampled `.ptrace` is roughly **constant size
regardless of grid**.

`decodeDynSampled` reverses this: decode recipes and recorded blocks, walk the plan
reconstructing each block's coordinates from G, and for each synth bit call
`SynthBlock` at that coordinate; recorded blocks are consumed in order and get their
coordinates from G.

### Grid extrapolation (`ExtrapolateGrid`)

`ptrace synth --grid GxHxD` instead fits recipes on the (small) input blocks, uses
the first block as the shape template, and synthesizes **every** block of a new,
larger grid — generating a large trace from a small one. This has no ground truth
at the new size and is therefore **unverified by construction**; a committed
ground-truth trace must gate any production use. Blocks whose template contains an
unmodeled access cannot be extrapolated and are reported, not emitted.

## 7. Verification (`cmd/ptrace`)

- `ptrace verify <traces>` converts (full mode), expands, and asserts every
  kernel's `.traceg` is byte-identical to the original; reports modeled coverage
  and size ratio.
- `ptrace synth <traces>` does the same for sampled mode, and additionally reports
  the **instrumented-block fraction** (recorded / total), which is the
  collection-wall-time proxy.
- `ptrace holdout <traces>` fits recipes on a sub-grid and synthesizes the held-out
  blocks, reporting how many reproduce byte-exactly — a direct synthesizability
  measurement that does not change what is stored.

## 8. Measured behavior

Synthetic affine kernel (8 warps, 6 insts/warp), sampled `.ptrace` stays ~1.7 KB
across all sizes, reconstruction byte-identical:

| grid | blocks | accelsim | full (v3) | sampled (v4) | instrumented |
|------|-------:|---------:|----------:|-------------:|-------------:|
| 16×16   | 256   | 39 KB  | 25×  | 24×     | 4/256 |
| 64×64   | 4096  | 608 KB | 130× | 374×    | 4/4096 |
| 128×128 | 16384 | 2.4 MB | 153× | 1491×   | 4/16384 |
| 256×256 | 65536 | 9.8 MB | 130× | 5981×   | 4/65536 |

Full mode is `O(dynamic instructions)` and plateaus ~130–150×; sampled mode is
`O(static program + grid descriptor)`, so its ratio scales with problem size. (The
6 real P0 kernels measured 9–16× in full mode — a small-trace artifact dominated by
fixed overhead; see [`ptrace_p0_findings.md`](ptrace_p0_findings.md).)

## 9. Offline SASS analysis (`tracer/sass`) — drives Mode-2 sampling

Everything above learns structure *from the dynamic trace*. The `sass` package
learns it *from the binary, before running*, so a sampling tracer knows what to
capture versus synthesize a priori. `sassan <binary>` runs `cuobjdump -sass` and,
per kernel:

- **Backward-slices each `LDG`/`STG` address register** to its provenance
  (builtin index / kernel arg / a memory load), classifying the access as
  `affine` (tier 0–3), `indirect` (tier 5, base derives from a loaded value), or
  `computed` (non-affine register math — PRNG/hash/bit-reverse, tier 4). The arg
  bases (`argN+offset`) it passes through are recovered too — the symbolization
  Mode-1 needs.
- **Classifies each guarded branch** by slicing its predicate: `uniform`,
  `index`-determined (synthesize the path/active-mask from indices — "what warp
  needs to take"), or `data`-dependent (must sample); loop back-edges are flagged,
  so a data-dependent trip count is identified as must-capture.
- **Flags cross-launch determinism**: absence of atomics, clock reads, and (a
  kernel-level heuristic) loop-carried bitwise mixing. No nondeterminism ⇒
  relaunches are byte-identical ⇒ store once, reference the rest.

The slice is a path-insensitive last-writer walk: exact for straight-line address
arithmetic, approximate across control flow (loop-carried PRNG state is caught by
the kernel-level mixing heuristic, not the slice). It is a **conservative
classifier, not a prover** — anything unresolved is pushed to the must-capture
side, and the §6 verify-or-fallback gate remains the correctness backstop. On the
P0 suite it independently reproduces the dynamic split (regular dense kernels
REGULAR; fft COMPUTED via `BREV`; spmv IRREGULAR; gups COMPUTED via xorshift).

## 10. Lossy statistical gathers — tier-7 (`tier7.go`, `cache.go`)

Tiers 0–6 are lossless, but a data-dependent gather (SpMV `x[col[]]`) is
near-maximal entropy — its index stream *is* the sparse matrix, so it cannot be
compressed losslessly (~10 bits/access, irreducible). For **cache/performance
simulation**, though, the exact addresses don't matter — only the pattern the
memory system sees. Tier-7 exploits that:

- **Model.** `StatModel` describes the stream's cache-relevant statistics: the
  working set (`base`, `elem`, index `range`), per-warp active-lane counts, and —
  only if needed — an index-frequency histogram for hot/cold skew. Indices are
  drawn i.i.d. from that distribution; each warp-load's lanes are drawn
  independently so the **coalescing** (memory-transaction count) is reproduced.
- **Gate = cache-behavior equivalence.** `FitAndGate` fits the simplest model
  (uniform, then histogram), synthesizes a stream, and accepts it only if it
  matches the original's **LRU miss-rate curve** (across L1–L2 sizes, via the
  stack-distance model in `cache.go`) *and* its **mean transactions/load**, within
  tolerance. The metric preserved is the metric validated. A model that fails is
  rejected and the access stays in the lossless tier-5 residual.
- **Lossy and opt-in.** The regenerated addresses are functionally wrong; tier-7
  is for timing/cache simulators only and is never used for functional replay.

On the SHOC spmv gather this turns 40 KB into 16 × 15-byte uniform models (~171×),
matching the miss curve through its knee and the transaction count within ~0.5%.
Because the model is parameterized by working-set size and access count, it also
gives a **lossy cross-size** path: generate the large-problem gather pattern from
small-run statistics (the irregular-kernel case §6's exact extrapolation can't do).

## 11. Scaling extrapolation (`scale.go`) — one small run → many sizes

§6's sampled synthesis extrapolates the *spatial* axis (more thread blocks).
`scale.go` extrapolates the *temporal* axis: a larger per-thread-work size is the
same loop run more times. A regular kernel's warp stream is
`prologue + body*k + epilogue`; `detectLoop` finds the dominant consecutively-
repeating segment (the body) and its count, and `scaleWarp` re-emits it `k'` times
for the target — as `(taken iteration)×(k'-1) + (exit iteration)`, so the
back-edge branch's mask (taken on every iteration but the last, where it exits) is
reproduced exactly. Memory inside the body gets its per-iteration address from the
recipe's `occ` term; prologue/epilogue are copied verbatim.

`ptrace scale <sample> <from> <to> <truth>` generates the target size and compares
it block-by-block to a *real* trace of that size. On fp32, a sample at fmas=256
reproduces the real 512 / 1024 / 8192 traces with **1023/1024 blocks byte-
identical**; the single differing block differs by one token — the run-specific
`cudaMalloc` output pointer (the verifier classifies absolute-address diffs as
expected and flags anything else as structural).

**The load-bearing caveat: sample within the target's code-path regime.** nvcc
emits *different code by trip count* — a remainder loop at tiny sizes (one set of
PCs) and a fully-unrolled body at larger sizes (different PCs). So fmas=8 cannot
generate fmas=64: the target's instructions never appear in the small sample. Take
the sample from the same unrolled regime as the target — which is the expensive
regime anyway, so this is exactly where it pays off (the fmas=65536 config that
times out to full-trace is pure loop repetition, generated in milliseconds).

## 12. Known limitations

- **Template-class synthesis.** `SynthBlock` picks a modeled instruction's class
  from the *template* block's `(mode, tail)`. If a multiclass recipe's class varies
  by block coordinate, the template's choice may be wrong for other blocks — those
  blocks simply fail verification and fall back to recorded (correct, but less
  synthesized). Single-class regular kernels (the wall-time targets) are unaffected.
- **Block-invariant shape assumption.** Synthesis copies the template's warp count,
  per-warp instruction count, and masks. Blocks that differ (e.g. predication at
  grid boundaries) fall back to recorded.
- **Absolute base addresses.** Bases are stored/extrapolated as absolute values
  anchored by the fitted intercept; they are not yet symbolized to `argN+offset`, so
  cross-size extrapolation assumes the base layout is itself affine in the indices.
- **Tiers 4–5 not modeled.** PRNG-from-seed and recorded-index gathers are stored in
  the residual column (lossless) but not yet synthesizable.
- **No live tracer.** The method runs on already-collected traces; instrumenting
  only the sampled blocks at collection time needs the NVBit back-end fork (P1b).
- **Scaling extrapolation needs a same-regime sample and exact run addresses.**
  It works only for regular kernels with a loop-invariant body, requires the
  sample to be in the target's compiler code-path regime (§11), and reproduces the
  trace only up to run-specific absolute addresses (the output pointer, shmem/local
  bases) — exact cross-run match needs base-address symbolization.
- **Tier-7 is i.i.d. and not yet wired into expand.** The statistical model
  assumes independent draws, so correlated/bursty gathers (banded matrices, BFS
  frontiers) need a higher-order model; set-associative conflict misses need an
  address-mod-sets feature; and the encoder is currently a standalone fit/measure
  (`statfit`), not yet emitted into a `synth --lossy` full trace.
